# Internationalization

How text is translated, and how to add a string or a language.

The app uses Tcl's `msgcat` (see [msgcat](../tcl-notes/tcl/msgcat.md)). Its commands (`mc`, `mcset`, ...) are available globally.

## Using a string

Keys are identifiers, not the text itself. Areas are separated with dots, and
the strings of one screen share a prefix; texts used by several screens go
under `common.`:

```tcl
ttk::label  $win.title -text [mc suppliers.title]
ttk::button $win.save  -text [mc common.save]
```

Call `mc` when the widget is **built**, so the catalog must already be loaded
(the startup order guarantees this, see [Overview](overview.md#startup-order)).

## Adding a string

Add the key to every catalog in `msgs/`:

```tcl
mcset es suppliers.title Proveedores
mcset es suppliers.empty.name "El nombre no puede estar vacío."
```

A key that is missing in the active language is shown as the key itself
(`suppliers.title`). That is how you spot a forgotten translation.

For text with values, use `format` placeholders and pass the values to `mc`:

```tcl
mcset es items.count "%d productos"
mc items.count 3
```

Messages for database errors are looked up by key too, see
[Handling constraint errors](database.md#handling-constraint-errors).

## Adding a language

1. Copy an existing catalog in `msgs/` to `msgs/<locale>.msg`. Locale codes are lowercase (`en`, `pt_br`).
2. Change the locale in every `mcset` line and translate the text.
3. Save it as UTF-8.

Nothing else needs to be registered.

## Which language is used

At startup the system locale is used if there is a catalog for it. If not, the app
falls back to the default locale, a constant set at startup (see [Overview](overview.md#what-is-global)).

The default locale is **not** loaded as a fallback for the missing keys of another
language, so a new language has to be complete.
