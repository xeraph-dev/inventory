# Internationalization

How text is translated, and how to add a string or a language.

The app uses Tcl's `msgcat`. Its commands (`mc`, `mcset`, ...) are available globally.

## Using a string

Keys are identifiers, not the text itself. Areas are separated with dots:

```tcl
$tabs add [products-panel $tabs.products] -text [mc products]
wm title . [mc window.title]
```

Call `mc` when the widget is **built**, so the catalog must already be loaded
(the startup order guarantees this).

## Adding a string

Add the key to every catalog in `msgs/`:

```tcl
mcset es window.title Inventario
mcset es products Productos
```

A key that is missing in the active language is shown as the key itself
(`products`). That is how you spot a forgotten translation.

For text with values, use `format` placeholders and pass the values to `mc`:

```tcl
mcset es items.count "%d productos"
mc items.count 3
```

## Adding a language

1. Copy `msgs/es.msg` to `msgs/<locale>.msg`. Locale codes are lowercase (`en`, `pt_br`).
2. Change the locale in every `mcset` line and translate the text.
3. Save it as UTF-8.

Nothing else needs to be registered.

## Which language is used

At startup the system locale is used if there is a catalog for it. If not, the app
falls back to `DEFAULT_LOCALE` (`es`, in `main.tcl`).

The default locale is **not** loaded as a fallback for the missing keys of another
language, so a new language has to be complete.
